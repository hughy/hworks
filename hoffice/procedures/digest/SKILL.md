# Digest

Inputs: instance root, engine root, digest directory name, optional cadence, `period_start`, `period_end`, open digest branch `refs`, and `unattended`. The caller owns discovery and git. Read only remote shared activity, never local checkouts or `local` documents. All instance paths below are relative to the input root; templates and scripts are engine paths.

## Steps

1. Read the instance's `AGENTS.md`, `digests/<digest>/DIGEST.md` and each configured project's `README.md`, `STATE.md`, and `DOCS.md`. Missing or invalid config stops the run; point to `<engine>/templates/digest-config.md`. Read `extensions/access.md` if present for extra document access values; otherwise use only the engine values. Read the newest digest only in `digests/<digest>/` across the instance default branch and `refs`, ignoring `archive/` and other digest directories.
2. Window: cadence defaults from config. Honor explicit `period_start` and `period_end` inputs; otherwise end at run start in the configured timezone and start at this digest's newest `period_end`, including open refs. With no previous digest, mark a baseline and default the start to end minus `baseline_lookback_days` (default 7). Require valid timestamps with start before end. Clamp to `max_lookback_days`, recording any clamp under Coverage gaps. Use an inclusive start and exclusive end; extensions convert timestamps to their source format.
3. For every configured `sources` entry, read `<instance>/extensions/sources/<kind>.md` and pass its `settings`, window, and previous source markers. Missing extensions, tools, auth, and unreadable items are coverage gaps, not permission to guess another system. Each extension defines listing, pagination, item links, and markers. Record changed, unchanged, and unreadable sources, including missing extensions. If every source is unreadable, stop as a failed run. No configured sources is invalid config.
   - Read chat first: cover the whole window, including replies during it to older parents; honor configured searches, bot filters, and private-source settings. Include only authorized channels.
   - Then documents, tracker, and code-host activity through their extensions. Select registered documents from project `DOCS.md` per settings; skip this digest's own publication. Compare modification/version markers. Without previous content, say a diff is unavailable and describe only what was read. Include merged changes and direct commits; never clone or inspect a local checkout.
   - Honor configured repository watches: paths filter files, keywords match paths or commit messages case-insensitively. Read matching files at the newest commit, skip registered files already covered, propose registry rows for new ones, and record unreadable matches as gaps.
   - Follow document links in material messages and tracker events through the matching configured source extension. Read unregistered linked documents, report what they are and any verified window change, record source markers, and propose registry rows. Unreadable links are gaps; never infer contents.
4. Build Current status as of `period_end` from remote work in progress or review, open changes, and blockers. `STATE.md` from the instance default branch is background and drift evidence, not proof of current remote state.
5. Material-change test: decisions, commitments, open questions, document edits, merged changes, and tracker events count. Greetings, reactions, alerts, and scheduling chatter do not. A baseline is always material. If quiet and `open_pr_when_quiet` is false, write no file and continue to rendering with `No material changes since <period_start>, checked <period_end>.`; return `quiet`.
6. Otherwise write a new `digests/<digest>/<period_end date>-<cadence>.md` from `<engine>/templates/digest.md`. If present locally or in any ref, append `-<HHMM>` from `period_end`; if that also exists, stop rather than overwrite. Fill all fields, including projects, baseline, publication URL (or null), and every source checked. Digests are append-only.
7. Body rules:
   - Use only project labels and order from config. Put an item spanning projects under the project it most concerns. Place items by content, not just a source's default project. Current status has every project; omit other empty project subsections. Summary has no subsections. Write `None.` for empty sections. Background appears only in the baseline.
   - Link every artifact with descriptive text: changes, commits, issues, channels, message permalinks, and documents with their relevant section or tab. Paraphrase and link; never mirror chat or quote more than one sentence.
   - Cite each claim. Separate proposals from decisions. Name people for decisions and questions; otherwise describe actions and systems. Write blamelessly.
   - Omit credentials, customer or personal data, and unauthorized source content. Mark private-channel material `(private channel)`. Never copy `local` documents or describe unread documents.
   - Tracker events are dated history, separate from Current status.
8. Propose `STATE.md` changes and `DOCS.md` rows in the digest, grouped by their destination file. Do not apply them. Interactive runs show Summary, Current status, and proposals; offer approved edits as a separate follow-up, outside this digest run's worktree. Rewrite STATE.md, never append it; retain source priority: code/config, registered external authority, STATE.md, notes, then sessions/digests. Decisions are superseded by new decisions, never edited in place.
9. Run `node <engine>/scripts/render-digest.mjs --check <digest file> --config <instance>/digests/<digest>/DIGEST.md`. Fix each finding with a link; if no link can be found, remove the identifier and record a coverage gap. Repeat until passing. Patterns come from config, not any assumed system.
10. Create an output directory outside tracked content and render with `node <engine>/scripts/render-digest.mjs <digest> <out.html> --instance <instance>`, adding each `--ref <ref>` and, on quiet runs, `--quiet "<note>"`. The rolling page shows the newest Current status and up to `rolling_days` digests, newest first, including open refs, with older sources linked. A quiet run without an existing log has nothing to render; report that gap without inventing a digest.
11. Scan the rendered page for secrets and personal or customer data. On a hit, skip publishing and record a gap. Read `extensions/publisher.md`; if missing, report the HTML path and stop before publishing. Otherwise pass config's `publisher` map (or `{}` when absent) unchanged to the publisher extension, without interpreting its contents. Follow the extension for disk-based upload, version replacement, and URL/version read-back. Publish only to config `slug`. Interactive runs get approval for each write; unattended runs require the prompt to name this slug as authorized. Do not infer publication success or version from local state. Publish failures are coverage gaps, not failed runs.
12. After verified publication, if config `url` is null write the returned URL and `first_published` (today). These are the only config edits. Set `url` in the new digest, if one exists. Return digest path or `quiet`, HTML path, window, URL, counts changed/unchanged/unreadable, coverage gaps, and Summary text. If publication is unavailable, still return the local digest and coverage report to the caller.

## Unattended

Never ask questions: take the conservative option and record gaps. Write only under `digests/<digest>/` and the temporary render directory; a publisher extension may define an upload staging path. Never edit projects, STATE.md, DOCS.md, decisions, sessions, or repo cards. Never write to source systems. Publish only the explicitly authorized slug. A missing/invalid config or every source unreadable fails the run; one source or publication failure does not. Quiet runs create no commit or PR.
